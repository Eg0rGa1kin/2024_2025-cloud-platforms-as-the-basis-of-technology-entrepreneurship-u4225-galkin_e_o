Google Cloud Run — это управляемый сервис от Google Cloud, который позволяет разработчикам запускать контейнеризованные приложения без необходимости управлять инфраструктурой. Он предоставляет возможность развертывания и автоматического масштабирования приложений, основанных на контейнерах, и идеально подходит для микросервисной архитектуры.

3) Анализ логов и метрик: В процессе анализа логов и метрик были выявлены ключевые показатели производительности, такие как использование ресурсов и время отклика. Они дают возможность оценить эффективность работы сервиса и выявить потенциальные проблемы.  
Описание метрик в Google Cloud Run:  

  - Количество запросов (Request count): Общее количество входящих запросов к вашему приложению за определенный период времени. Эта метрика помогает понять, насколько активно используется ваше приложение.  

  - Задержка запросов (Request latencies): Время, необходимое для обработки запросов. Обычно измеряется в миллисекундах и может быть представлено как среднее, медианное или 95-й процентиль. Позволяет оценить производительность вашего приложения.  

  - Количество экземпляров контейнеров (Container instance count): Общее количество экземпляров контейнеров, запущенных для обработки запросов. Эта метрика помогает понять, сколько ресурсов используется для обслуживания нагрузки.  

  - Время работы оплачиваемых контейнеров (Billable container instance time): Время, в течение которого экземпляры контейнеров были активны и за которое вы будете оплачивать услуги. Эта метрика важна для оценки затрат на использование Cloud Run.  

  - Использование CPU контейнера (Container CPU utilization): Процент использования процессора контейнера. Позволяет отслеживать, насколько эффективно используются вычислительные ресурсы и есть ли необходимость в их масштабировании.  

  - Использование памяти контейнера (Container memory utilization): Объем используемой памяти контейнера. Эта метрика помогает определить, достаточно ли выделенных ресурсов или требуется их увеличение.  

  - Отправленные байты (Sent bytes): Объем данных, отправленных вашим приложением в ответ на запросы. Это может включать в себя HTML, JSON, изображения и другие данные.  

  - Полученные байты (Received bytes): Объем данных, полученных вашим приложением от клиентов. Это может включать в себя данные запросов, такие как JSON или файлы.  

  - Максимальное количество одновременных запросов (Max concurrent requests): Максимальное количество запросов, обрабатываемых одновременно вашим приложением. Эта метрика помогает понять, насколько хорошо приложение справляется с увеличенной нагрузкой.  

  - Задержка запуска контейнера (Container startup latency): Время, необходимое для запуска контейнера и начала обработки первого запроса. Высокая задержка может указывать на проблемы с производительностью или необходимость оптимизации времени запуска.

5) Переключение трафика: Проведено переключение трафика между версиями сервиса, что позволило сравнить их производительность и выявить различия в работе. Это также продемонстрировало возможности Cloud Run по управлению версиями и трафиком.  
При управлении трафиком 50% на 50% запросы будут равномерно распределяться между двумя версиями приложения. Это означает, что каждая версия будет обрабатывать примерно половину всех входящих запросов. Важно следить за тем, как каждая версия справляется с нагрузкой, чтобы убедиться, что распределение действительно 50/50 и что ни одна из версий не перегружена.
<image src="/Снимок экрана 2024-10-25 в 13.50.58.png">
Далее настроили балансировщик нагрузки так, чтобы он направлял 90% входящих запросов на новую версию приложения (на порт 8090) и 10% на старую версию (на порт 8080). Важно следить за производительностью обеих версий. Это включает в себя сбор данных о времени отклика, частоте ошибок и других метриках, чтобы убедиться, что новая версия работает так, как ожидалось, и что старая версия не перегружена. Такой подход позволяет вам минимизировать риски при внедрении новой версии, одновременно получая данные о ее производительности в реальных условиях.
